# Сверка с настоящим Stratum 2000

Здесь собрано, что в Stratum Modern **сверено с оригиналом**, а что только
**проверено ядром само на себе**. Всё, чего нет в этом файле, считается
непроверенным, даже если в `docs/audit.md` отмечено «есть».

## Два способа сверки

### 1. Байт-код корпуса: компилятор оригинала как эталон

В каждом `.cls` корпуса лежит секция `0x0d` — байт-код, построенный
компилятором оригинала. `lang/compile.rs` строит такой же байт-код из текста,
и `stratum bytecode fixtures/` сравнивает их слово в слово.

```sh
cd core && cargo run -- bytecode ../fixtures            # сводка
cargo run -- bytecode ../fixtures --show 5              # подробно пять расхождений
python3 ../tools/disasm.py файл.cls                     # байт-код с именами
```

Совпадение подтверждает решения **компилятора**: разбор, приоритеты,
фазы `x`/`~x`, выбор перегрузок функций, порядок и типы переменных.

Итог сейчас: **422 из 471** уникальных имиджей совпадают слово в слово.
Остальные:

- 31 не компилируются текущей таблицей функций: тексты старых версий со
  старыми именами (`GetObjectSize2dy` → `GetObjectHeight2d`,
  `GetSchemeObject` → `GethObjectByName`) и старыми сигнатурами
  (`GetSpace3d(HANDLE, HANDLE)`). Оригинал исполняет их по сохранённому
  байт-коду, а компилятор установленной версии их тоже не примет.
- 18 расходятся в группировке операций одного приоритета (например,
  `x != ~x + y != ~y`). Современный компилятор оригинала группирует слева —
  см. пробы `grouping.txt` ниже, — так что это следы старых версий.
- Сворачивание `-число` в отрицательную константу встречается в обоих
  вариантах (видимо, настройка оптимизации); на значения не влияет,
  сверка принимает оба.

### 2. Исполнение в оригинале через Wine

`tools/verify_original.py` собирает из проб (`tools/verify/*.txt`,
строки `имя | выражение` и `> оператор`) модель, выполняет её ядром и
оригиналом (`SC200032.EXE проект.spj /run`) и сравнивает ответы. Модель
пишет ответы в файл потоком и вызывает `Quit(1)`.

С ключом `--compiler` текст пробы компилирует **сам оригинал**
(`SetModelText` на ходу), поэтому проверяются и компилятор, и машина.

```sh
python3 tools/verify_original.py tools/verify/math.txt --compiler
```

Нужны Wine и установленный Stratum 2000 (`~/.wine32`, переопределяется
`WINEPREFIX` и `STRATUM_EXE`).

| Набор | Что проверяет | Итог (--compiler) |
| --- | --- | --- |
| `strings.txt` | `Pos`, `Substr`, `Left`, `Right`, `Length`, `Upper` с кириллицей | 8 из 8 |
| `math.txt` | арифметика, `round`, `trunc`, `sgn`, `sqrt`, `exp`, `ln`, `lg`, `limit`, формат чисел в строке | 26 из 26 |
| `semantics.txt` | регистр кириллицы в именах, фазы `x`/`~x`, приоритеты, сравнение строк | 9 из 9 |
| `grouping.txt` | группировка `== != < - / ^ %` и скобок | 12 из 12 |

## Что сверка исправила в ядре

| Было | Стало | Как установлено |
| --- | --- | --- |
| `Pos(s, t, n)` игнорировал `n` | n-е вхождение, позиции с нуля; в примере справки ошибка (19 вместо 18) | Wine |
| `String(x)` печатал полную точность | формат `%g`, 6 значащих цифр: `1.41421`, `1e+20`, `1e-07` | Wine |
| `trunc(-2.7) = -2` | `-3`: у оригинала это округление вниз | Wine |
| `round(2.5, 0) = 3` | `2`: ровная половина — вниз (`round(-2.5, 0) = -3`) | Wine |
| «Скорость» и «скорость» — разные переменные | одно имя: компилятор оригинала регистр кириллицы не различает | Wine, `--compiler` |
| экспорт в `.cls` без байт-кода: оригинал исполнял пустоту | экспорт компилирует имиджи | Wine |

## Чего ещё нет

- Сверки многотактовых моделей (траектории «Солнечной системы», BALLS,
  PINBALL_) — значения в `core/tests/corpus.rs` пока получены самим ядром.
  Путь: снимок `.stt` оригинала после N тактов против снимка ядра.
- Сверки графики (снимки окон оригинала против нашего SVG).
- Проб для математических ошибок (`1/0`, `sqrt(-1)`): у оригинала они
  открывают окно ошибки, стенду нужно уметь его закрывать.
