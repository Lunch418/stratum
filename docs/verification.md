# Сверка с настоящим Stratum 2000

Здесь собрано, что в Stratum Modern **сверено с оригиналом**, а что только
**проверено ядром само на себе**. Всё, чего нет в этом файле, считается
непроверенным, даже если в `docs/audit.md` отмечено «есть».

## Два способа сверки

### 1. Байт-код корпуса: компилятор оригинала как эталон

В каждом `.cls` корпуса лежит секция `0x0d` — байт-код, построенный
компилятором оригинала. `lang/compile.rs` строит такой же байт-код из текста,
и `stratum bytecode fixtures/` сравнивает их слово в слово.

```sh
cd core && cargo run -- bytecode ../fixtures            # сводка
cargo run -- bytecode ../fixtures --show 5              # подробно пять расхождений
python3 ../tools/disasm.py файл.cls                     # байт-код с именами
```

Совпадение подтверждает решения **компилятора**: разбор, приоритеты,
фазы `x`/`~x`, выбор перегрузок функций, порядок и типы переменных.

Итог сейчас: **422 из 471** уникальных имиджей совпадают слово в слово.
Остальные:

- 31 не компилируются текущей таблицей функций: тексты старых версий со
  старыми именами (`GetObjectSize2dy` → `GetObjectHeight2d`,
  `GetSchemeObject` → `GethObjectByName`) и старыми сигнатурами
  (`GetSpace3d(HANDLE, HANDLE)`). Оригинал исполняет их по сохранённому
  байт-коду, а компилятор установленной версии их тоже не примет.
- 18 расходятся в группировке операций одного приоритета (например,
  `x != ~x + y != ~y`). Современный компилятор оригинала группирует слева —
  см. пробы `grouping.txt` ниже, — так что это следы старых версий.
- Сворачивание `-число` в отрицательную константу встречается в обоих
  вариантах (видимо, настройка оптимизации); на значения не влияет,
  сверка принимает оба.

### 2. Исполнение в оригинале через Wine

`tools/verify_original.py` собирает из проб (`tools/verify/*.txt`,
строки `имя | выражение` и `> оператор`) модель, выполняет её ядром и
оригиналом (`SC200032.EXE проект.spj /run`) и сравнивает ответы. Модель
пишет ответы в файл потоком и вызывает `Quit(1)`.

С ключом `--compiler` текст пробы компилирует **сам оригинал**
(`SetModelText` на ходу), поэтому проверяются и компилятор, и машина.

```sh
python3 tools/verify_original.py tools/verify/math.txt --compiler
```

Нужны Wine и установленный Stratum 2000 (`~/.wine32`, переопределяется
`WINEPREFIX` и `STRATUM_EXE`).

| Набор | Что проверяет | Итог (--compiler) |
| --- | --- | --- |
| `strings.txt` | `Pos`, `Substr`, `Left`, `Right`, `Length`, `Upper` с кириллицей | 8 из 8 |
| `math.txt` | арифметика, `round`, `trunc`, `sgn`, `sqrt`, `exp`, `ln`, `lg`, `limit`, формат чисел в строке | 26 из 26 |
| `semantics.txt` | регистр кириллицы в именах, фазы `x`/`~x`, приоритеты, сравнение строк | 9 из 9 |
| `grouping.txt` | группировка `== != < - / ^ %` и скобок | 12 из 12 |
| `matherr.txt` | значения при ошибках: `1/0`, `0/0`, `5%0`, `sqrt(-1)`, `ln`, `lg`, `exp` | 12 из 12 |
| `power.txt` | степени отрицательных чисел, `0^0`, переполнение | 9 из 9 |
| `random.txt` | первые значения `rnd` без зерна и после `randomize` | 7 из 7 |
| `arrays.txt` | номера `New()`, итоги `vInsert`, `vDelete`, `vGetCount`, `vGetType` | 13 из 13 |
| `windows.txt` | размер окна по умолчанию, рамка, каскад, `SetClientSize`, `SetWindowOrg`, экран | 28 из 28 |

Директивы файла проб: `% Ключ = число` — свойство проекта; `! оператор` —
выполнить на первом такте, `% Wait = N` — снять пробы через N тактов
(окно получает размеры не сразу); `@ папка Имя` — взять имидж со всей его
схемой из другого проекта (для проб окон и графики).

Отдельные опыты со схемами: `tools/verify_links.py` — значения связанных
переменных с разными значениями по умолчанию; `tools/verify_messages.py` —
порядок доставки `SendMessage` по классу и что видит получатель;
`tools/verify_phases.py` — связанная переменная без тильды после изменения
другим имиджем в том же такте и при вызове сообщением.

Пробы на ошибки идут в режиме «Не замечать» (строка `% MathMode = 3` в
файле проб). В режиме по умолчанию оригинал открывает окно «Математическая
ошибка» с кнопками «Остановить вычисления / Пропустить / Больше не
замечать»; `arcsin(2)` вешает оригинал даже в режиме «Не замечать».

### 3. Траектории: снимок состояния оригинала

`stratum instrument` берёт пример с родным байт-кодом его имиджей и
дописывает в начало текста корневого имиджа счётчик тактов: на такте N+1
модель вызывает `SaveObjectState` и `Quit`. Тот же проект исполняют оригинал
(в Wine) и ядро, затем `stratum sttdiff` сравнивает снимки.

```sh
W=~/.wine32/drive_c/verify
cargo run -- instrument ../fixtures/user/solar_system $W --ticks 100
(cd /tmp && WINEPREFIX=~/.wine32 wine 'C:\Program Files\Stratum\SC200032.EXE' 'C:\verify\project.spj' /run)
mkdir -p $W/verify && cargo run -- run $W --ticks 105
cargo run -- sttdiff $W/state.stt $W/verify/state.stt
```

«Солнечная система», 100 тактов, 39 экземпляров: **735 из 746** значений
совпадают, включая все числа траектории, строки и цвета. Расходятся 11
номеров графических объектов, которые модель создаёт на ходу: оригинал
удаляет и пересоздаёт часть объектов, и номера переиспользуются иначе. На
вычисления это не влияет.

Для любого примера это делает одной командой `tools/verify_trajectory.py`:

```sh
python3 tools/verify_trajectory.py fixtures/PROJECTS/samples/GIST --ticks 50
```

«Гистограмма» (GIST), 50 тактов со случайными числами: **84 из 84**.
«Мышь» (MOUSE), 50 тактов: **63 из 63**. «Шары» (BALLS), 13 шаров со
столкновениями через рассылку сообщений: **1458 из 1458**. «Солнечная
система» теперь 745 из 746: расходится один номер объекта, созданного на ходу.

`sttdiff` сопоставляет экземпляры по имиджу, handle на схеме и номеру
вхождения (у каждого шара свой `Engine#3`); `--all` печатает все расхождения.

## Чего ещё нет

- Часть линий связей в окне схемы оригинал оставляет с габаритом из файла
  (L1 #71, у krop BALLS #29–31), остальные пересчитывает; правило не найдено.
  На модели не влияет: связи в окне модели не видны и не ловятся мышью.

- Траекторий PINBALL_, 2d и других примеров.
- Размеры окон и экрана сняты в одном окружении (Wine, 1920×1080); на
  другом экране оригинал даст другие числа.
- Сверки графики (снимки окон оригинала против нашего SVG).
- Эталона для `arcsin(2)` и других ошибок, на которых оригинал зависает.
