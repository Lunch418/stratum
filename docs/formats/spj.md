# Форматы `project.spj` и `_preload.stt`

Восстановлено по файлам из `fixtures/`, проверено парсером
[`tools/spj_dump.py`](../../tools/spj_dump.py). Байт-порядок и строки — как в
[`.cls`](cls.md): little-endian, `str` = `u16 длина` + CP1251.

```
проверить корпус:  python3 tools/spj_dump.py --scan fixtures
посмотреть файл:   python3 tools/spj_dump.py fixtures/user/solar_system/project.spj
```

Итог по корпусу: 127 из 142 файлов разбираются полностью. Оставшиеся 15 — это
`DEFAULT.STT` и нумерованные снимки состояния в старой редакции (см. ниже);
все рабочие `_preload.stt` (67 штук) читаются.

## `project.spj`

```
+0  char[3]  "Ih" + вид: 'd' или 'f'
+3  u8       0
```

**Вид `d`** — сразу `str` с именем корневого имиджа, затем необязательные
блоки, каждый начинается с байта-маркера:

| Маркер | Блок |
| --- | --- |
| `'f'` (0x66) | `u8 0`, `u16 count`, далее `count` записей-свойств |
| `'g'` (0x67) | `u8 0`, `u16 count`, далее `count` переменных проекта |
| `0x00` | конец файла |

**Вид `f`** — сначала `u16 count` и записи-свойства, затем `u16` и `str` с
именем корневого имиджа.

### Запись-свойство

`u16 size`, `u8 тип`, `u8 длина ключа`, ключ (завершён нулём), значение
занимает остаток записи: для типа 0 — `u32`, для типа 2 — строка с нулём в
конце.

Встречающиеся ключи: `MathMode`, `user_name`, `user_email`, `user_addr`,
`PerIdle`, `run_mode`, `runtimer`, `vars_logset`, `vars_preload`.

### Переменная проекта

`u16 kind`, `u16 флаги`, при `kind == 2` ещё `u16 handle`, затем `str имя` и
`str описание`. Пример: `Osc3d/project.spj` объявляет `ScaleZ`, `ScaleY`,
`OffsetY`; `MENU/PROJECT.SPJ` — `State` с описанием «текущее состояние кнопки».

Не всякий `.spj` — проект: `PROJECTS/samples/ANATOMY/anatomy.spj` на самом
деле архив RAR с проектом внутри.

## `_preload.stt` — снимок значений переменных

```
str      "SC Scheme Variables"
str      имя корневого имиджа
u16      0x28 — размер записи
u16      формат (2)
u16      идентификатор
...      записи до конца файла, в конце 2 байта-терминатор
```

Запись: `u32 ref` (handle имиджа, к которому относится запись), `u16 флаги`,
`str имя класса`, `u32 отметка`, `u16 count`, далее `count` пар
`str имя переменной`, `str значение` (значение всегда текстом: `"0.01"`,
`"марс"`).

Именно отсюда среда восстанавливает стартовые значения при открытии проекта.

### Старая редакция

`DEFAULT.STT`, `_UPLOAD.STT` и нумерованные снимки (`1.STT`…`4.STT`) написаны в
более ранней редакции: после двух слов заголовка идёт повторно имя корневого
имиджа, а переменные хранятся не по именам, а по индексам (`u16`-пары). Парсер
распознаёт такие файлы и сообщает об этом явно. Для открытия проектов они не
нужны — стартовые значения лежат в `_preload.stt`.
