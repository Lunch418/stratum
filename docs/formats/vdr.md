# Формат `.vdr` — векторная графика Stratum 2000

Формат графического пространства: отдельные файлы `.vdr` (иконки контролов,
рисунки для `LoadSpaceWindow`) и три секции имиджа `.cls` — иконка (`0x08`),
рисунок имиджа (`0x09`, его показывает `OpenSchemeWindow`) и графика листа
схемы (`0x0c`). Восстановлено по 369 блокам корпуса; парсер
[`tools/vdr_dump.py`](../../tools/vdr_dump.py) читает 356 из них, остальные 13
содержат вложенные 3D-пространства (сигнатура `3D`) — этап 5.

Little-endian; `str` = `u16 длина` + CP1251. Внутри `.cls` перед блоком стоят
`u32 0` и `u32 размер`.

```
python3 tools/vdr_dump.py fixtures/library/CONTROLS.LIB/HGAUGE1.VDR
python3 tools/vdr_dump.py --scan <папка с блоками>
```

## Поколения формата

| Версия (u16 после `2D`) | Где | Числа | Размеры записей |
| --- | --- | --- | --- |
| `0x0102`, `0x0103` | старые примеры (BALLS, TOE) | `i16` | нет |
| `0x0201`, `0x0202` | библиотека, большинство примеров, все `.vdr` | `f64` | нет |
| `0x0300` | проекты 2010-х, «Солнечная система» | `f64` | есть: у каждого чанка и каждой записи |

Числа (`num`) — координаты, размеры, точки: `i16` до 0x0200, `f64` начиная с
0x0200. При наличии размеров неизвестная запись просто пропускается; без них
каждая запись должна быть разобрана до байта.

## Заголовок

Версии 1.x–2.x:

```
"2D"  u16 version  u16 version2
u32 header_size (0x5e)   u32 tools_at
num org_x, org_y         num scale_x, scale_y     num win_w, win_h
str  путь к базе иконок ("C:\SC3\data\icons\")
u8[8] 0   u32 0xffffffff   u16
```

`tools_at` указывает на два байта **до** начала секции инструментов (за
последним объектом): читать `u16` по `tools_at + 2`, дальше идут чанки
инструментов.

Версия 3.x:

```
"2D"  u16 version  u16 version2   u16   u32 size
6 × f64 (те же org/scale/win)   u16 flags   u8[8]
```

## Чанки

```
u16 id   [u32 size — только 3.x, включает id и size]
u16 count   u16 capacity   u16 delta      (capacity/delta — параметры массива)
[u8 1  u16 root — у списков объектов и инструментов; root = 0xffff]
count × запись
```

| id | Что | Запись |
| --- | --- | --- |
| 1020 | объекты | см. ниже |
| 1021 | Z-порядок | `u16` handle (без заголовка `u8 u16`) |
| 1004 | карандаши | `color u32, style u16, width u16, rop u16` |
| 1005 | кисти | `color u32, style u16, hatch u16, rop u16, dib u16` |
| 1006 / 1007 | растры / растры с маской | BMP целиком (`BM` + `bfSize`), для 1007 второй BMP — маска; в 2.x ещё 8 байт |
| 1008 | шрифты | LOGFONT-подобно: `i32 height, i32 width, i32 weight`, атрибуты, имя гарнитуры (30 байт с нулём) |
| 1009 | строки | `str` |
| 1010 | тексты | вложенный чанк 1011 |
| 1011 | фрагменты текста | `fg u32, bg u32, font u16, string u16` (без заголовка `u8 u16`) |
| 1022 | параметры листа | одна запись типа 34, 36 байт |

Типы инструментов (первое `u16` записи): 101 карандаш, 102 кисть, 103 растр,
104 растр с маской, 105 шрифт, 106 строка, 107 текст, 110/111 — ссылка на файл
базы иконок (`str` имя файла, например `SYSTEM.DBM`).

Общий заголовок записи инструмента:
2.x — `u16 type, u16 refs, u16 handle`; 3.x — `u16 type, u16 size, u16 0,
u16 refs, u16 handle` (у растров 103/104 поля `u16 0` нет).

## Объекты (чанк 1020)

Заголовок записи:
2.x — `u16 type, u16 handle, u16 flags, str name`;
3.x — `u16 type, u16 size, u16 0, u16 handle, u16 flags`, а имя — в блоке
расширения в конце записи: `u16 0xCD, u32 len (включая эти 6 байт), байты`.
Если имя пустое, блока нет.

Размер записи в 3.x считается от поля `type` до конца записи включительно.

| type | Объект | Тело после заголовка |
| --- | --- | --- |
| 20 | полилиния | `num x,y,w,h`, `u16 pen, u16 brush, u16 n`, `n × (num, num)`; в 2.x/3.x затем `u8 extra` и `extra` байт вложения (стрелки) |
| 21 / 22 | растр / растр с маской | `num x,y,w,h`, `4 × num` — прямоугольник в источнике (`SetBitmapSrcRect2d`), `u16`, `u16 dib` |
| 23 | текст | `num x,y,w,h`, `u16 text` (инструмент 107), 18 байт |
| 26 | интерфейсный элемент | `num x,y,w,h`, `str class` («Button», «Edit», «ListBox»…), `str caption`, `u16`, `u32 style`, `u16`, `u16 100`, `u16 w, u16 h`, `u16` |
| 3 / 4 / 5 | группа | вложенный чанк 1021 — список handle дочерних объектов |
| 24 | проекция 3D | `num x,y,w,h`, `u16 пространство` (место инструмента `3D` в чанке, с нуля), `u16 камера` |

Флаги объекта: `0x8000` — невыбираемый; `0x1000` встречается у объектов
внутри групп.

Координаты объекта — в системе пространства; `org` заголовка задаёт сдвиг
окна, `scale` — масштаб (100 = 1:1).

## Данные объектов и гиперссылки (`0x03FE`)

Закладки «Гипербаза», «Переменные» и параметры самого листа хранятся блоком
данных `0x03FE`:

- 3.x — блок расширения в конце записи объекта, после имени (`0xCD`):
  `u16 0x03FE, u32 длина (с этими 6 байтами), данные`;
- 2.x — список после инструментов: `u32, u16`, затем записи
  `u16 1, u16 handle, u16 0x03FE, данные` (объект) или
  `u16 2, u16 0x03FE, данные` (сам лист), `u16 0` — конец списка; за ним
  строка `End Of File <!>`.

Данные: `u16 версия (1 или 2), u16 5, u16 2, u8 число элементов`, элементы
`u16 номер, u16 длина, байты`. Встречаются номера `0x0a` — гиперссылка,
`0x0d` — переменные объекта: пары `переменная этого имиджа,переменная или
псевдоним другого имиджа` через `;` (`_HObject,_HPrev;out,in` — в «Роботе»
связи между такими имиджами соединяют `_HObject→_HPrev` и `out→in`), у листа
`0x01` (34 байта) и `0x0b` (8 байт).

Гиперссылка (`0x0a`) — поля `u16 номер` + значение: `1` — цель, строка
(`str`: имидж, файл `.vdr` или системная команда `CM_PREVPAGE`); `4` —
режим, `u16` (0 открыть окно, 1 приложение, 2 проект, 3 ничего,
4 системная команда). Отсутствующее поле — по умолчанию: пример «hyper»
хранит у переходов только цель. Номера полей окна, объекта и эффекта
(2, 3, 5) в корпусе не встречаются и приняты по порядку аргументов
`SetHyperJump2d`.

Проверка номеров полей (достоверность: 1, 2 и 4 - подтверждены, 3 и 5 - низкая):
- корпус: разобраны гиперссылки всех проектов `fixtures/PROJECTS/samples` и
  `fixtures/add.lib` (10 различных записей: окна `window_2..7`, `StratumClass_*`,
  `c:\z.vdr`, `CM_PREVPAGE`); во всех только поля 1 (строка-цель) и 4 (режим,
  `u16`), других номеров ни разу нет;
- оригинал: в `sccore32.dll` есть лишь имя элемента `Obj_Hyper` (0x0a) и
  `Space_Hyper`; имён полей внутри ссылки в двоичном файле нет, а запись/чтение
  полей лежит в таблице функций без текстовых имён (`SetHyperJump2d` - функция
  755 в `template/Graph2d.tpl`), без дизассемблирования не найти; запуск
  оригинала без X не проверялся (Wine не наш);
- диалог `OBJ_HYPER` (docs/original/dialogs.md): стиль (режим), цель, объект,
  эффект (+ «Настройка...»), окно и ещё одно поле id 617 - порядок полей диалога
  не совпадает ни с порядком аргументов, ни с номерами, поэтому он не помогает;
- опыт в Wine (оригинал читает файл, StdHyperJump по объекту): в .vdr с
  гиперссылкой из полей 1 (цель = имя имиджа) и 2 (строка `WINX`) переход
  открыл окно с именем `WINX` (GetWindowSpace("WINX") = 2) - **поле 2 = окно
  подтверждено**; поля 3 и 5 оригинал читает без ошибок (проект и окно
  грузятся), но их действие не проверено: WM_HYPERJUMP имиджу из поля
  «Объект» в опыте не пришёл ни при каких путях (`Probe`, `\\Probe`,
  `..\\Probe`, `Pg\\Probe`) - и через файл, и через SetHyperJump2d во время
  работы, поэтому отсутствие сообщения нельзя считать признаком неверного
  номера. 3 = объект, 5 = эффект остаются предположением (по возрастанию);
- как собрать пробу: взять .vdr с гиперссылкой и заменить её блок 0x03FE
  (тег, `u32` длина с тегом, тело `write_hyper`) - длина блока входит в
  размер записи объекта (`u16 тип, u32 размер` включает блоки 0xCD и 0x03FE),
  размер файла (смещения 4 и 16) и размер чанка 1020; без правки любого из
  трёх оригинал не открывает проект;
- поле id 617 диалога (возможно, параметры эффекта) ядром не хранится. Чтение
  терпимо: неизвестный номер обрывает разбор, разобранное остаётся. Чтобы
  закрыть оставшееся, нужен снимок реального сохранения из GUI оригинала
  (диалог объекта -> Гипербаза с заполненными окном, объектом, эффектом).
Ядро разбирает только гиперссылки; прочие элементы данных
объекта (переменные объекта) хранятся как есть и пишутся обратно при правке
рисунка. Данные самого листа (запись `u16 2`): элемент `0x01` (34 байта: смещение, шаг сетки `2 × f64`, `u16` флаги) - то же, что запись типа 34 чанка 1022 в 3.x (id 1022 = 0x03FE); ядро читает его в `page` и пишет как 3.x.

## Трёхмерное пространство (инструмент `3D`, чанк 1012)

Запись инструмента: `u16 0x4433` («3D»), в 3.x `u32 размер`, `u16 номер`;
дальше чанки как у листа: 1021 — объекты верхнего уровня, 1020 — объекты,
в 3.x ещё 1024 — материалы (пока хранятся как есть). Заголовок записи
объекта: 2.x — `u16 тип, u16 handle, u16 флаги, str имя`; 3.x — `u16 тип,
u32 размер, u16 handle, u16 флаги`, имя — блок `0xCD` в конце.

| тип | объект | тело |
| --- | --- | --- |
| 10 | тело из точек | `u16` (материал?), `u16 n`, `n × 3 f64` точки, `u16 m`, `m ×` примитив, `16 × f64` матрица (строками, перенос в четвёртой), `u16` |
| 11 | камера | 200 байт: `u16, u16`, положение, направление, «верх» (`3 × f64` каждое), фокус, дальняя и ближняя плоскости, размер кадра `3 × f64`, смещение `2 × f64`, `2 × f64`, `u32`, имя способа отрисовки (32 байта, «Zbuffer»), `u16` тип отрисовки, `u8` флаги, `u8` перспектива, `u32` фон — поля `po…` имиджа Camera3d, сверено по T80 |
| 12 | свет | 88 байт: `u16 88, u16 вид (0 точечный, 1 с направлением), u32 цвет 0x00BBGGRR, 3 × f64 положение, 3 × f64 вторая точка (у вида 1), 3 × f64 резерв (нули)`; разбор - `LightParams` в space3d.rs, имена полей по корпусу (T80, ENGINE, IRONCLAD), без сверки в оригинале |
| 3–5 | группа | вложенный чанк 1021 — дочерние объекты |

Примитив: `u16 k, u16 слои, u16 флаги, u32 цвет, k × u16` номера точек,
`k·слои × (f64 u, f64 v)` — текстурные координаты.

Заголовок 3.x тоже бывает длиннее: у ROBOT3.VDR флаги = 1, за восемью
байтами ещё блок в 60 байт (прямоугольник, сетка). Ядро ищет первый чанк по
id и размеру. Заголовок листа 2.x бывает длиннее 0x5e (у рисунков с 3D — ещё
прямоугольник и сетка): чанки начинаются по размеру из первого поля + 2.

## Что не разобрано

- Материалы: в 2.x-рисунках корпуса чанка 1024 нет вовсе (поле `u16` тела хранит только номер), в 3.x - см. выше.
- Точная раскладка LOGFONT (высота, толщина и гарнитура читаются надёжно,
  остальное — сырые байты).
- Назначение `u16` перед `dib` у растров, 18 байт у текста, полей `u16` у
  контролов.
- Запись 34 в чанке 1022 (сетка/лист).
