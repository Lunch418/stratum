# Формат `.cls` — имидж (класс) Stratum 2000

Спецификации не существует; всё ниже восстановлено по 660 файлам из `fixtures/`
(библиотека, 45 примеров, учебные проекты) и проверено парсером
[`tools/cls_dump.py`](../../tools/cls_dump.py): **660 из 660 файлов разбираются
полностью**, все 1376 записей оглавления сходятся с фактическим положением
секций.

Порядок байт — little-endian. Строка (`str`) — это `u16 длина` + байты в CP1251
(без нулевого терминатора). Смещения в тексте — от начала файла.

```
проверить корпус:  python3 tools/cls_dump.py --scan fixtures
посмотреть имидж:  python3 tools/cls_dump.py fixtures/library/CONTROLS.LIB/CHECKBOX.cls
```

## Общая структура

```
+0   char[2]  "SB"
+2   u32      версия: 0x3001 (31 файл), 0x3002 (217), 0x3003 (412)
+6   u32      body_end — смещение конца тела (см. «Хвост»)
+10  u32      index_size — размер оглавления в байтах = 6 × число записей
+14  str      имя имиджа
     ...      последовательность секций: u16 id + тело секции
     u16      0x0000 — маркер конца тела (может отсутствовать)
     ...      оглавление: записи (u32 offset, u16 id) до конца файла
```

Смещения в оглавлении отсчитываются **не от начала файла, а от байта 6**
(сразу после сигнатуры и версии): реальная позиция секции = `offset + 6`. Это
проверено на всех 1376 записях корпуса.

В оглавление попадают только «тяжёлые» секции, которые среда читает по
требованию: `0x0a` текст (583 раза), `0x08` иконка (272), `0x0c` схема (262),
`0x09` рисунок (140), `0x0e` описание (119). Остальные секции читаются
последовательно.

### Хвост

Поле `body_end` указывает на **тело последней секции**, а не на её id. Файл,
записанный полной версией среды, заканчивается так:

```
0x15 0x00   id секции «отметка времени»
u32         время записи (unix time)
0x00 0x00   маркер конца тела     <- body_end указывает на u32 выше
...         оглавление
```

Отсюда `index_start = body_end + 6`. Для v3.001 отметки времени может не быть.

Единственное исключение в корпусе — `library/SYSTEM.SC/INTEGER.CLS`: заголовок
обещает одну запись оглавления, а её нет (файл-заглушка с примером псевдокода).

## Секции

| id | Что это | Тело |
| --- | --- | --- |
| `0x04` | флаги имиджа | `u32` (частые значения: 0x200, 0x10, 0x40, 0x4240) |
| `0x07` | связи схемы | `u16 count`, далее записи (см. ниже) |
| `0x08` | иконка | `u32 size`, затем `size − 4` байт: BMP 32×32, 4 бита на пиксель, следом маска |
| `0x09` | рисунок имиджа | `u32 size`, затем `size − 4` байт в формате `.vdr` (сигнатура `2D`) |
| `0x0a` | текст модели | `str` (CP1251, переводы строк CRLF) |
| `0x0b` | не разобрано | `u16`; встречается в 20 файлах |
| `0x0c` | схема | `u32 size`, затем `size − 4` байт в формате `.vdr` — графика листа схемы |
| `0x0d` | байт-код | `u32 words`, затем `words × 2` байт — результат компиляции текста |
| `0x0e` | описание имиджа | `str` |
| `0x0f` | переменные | `u16 count`, далее записи (см. ниже) |
| `0x11` | дочерние имиджи схемы | `u16 count`, далее записи (см. ниже) |
| `0x14` | номер иконки в наборе | `u16` |
| `0x15` | отметка времени | `u32` unix time |
| `0x16` | файл набора иконок | `str`, например `system.dbm` |
| `0x1e` | уравнения | непрозрачный блок до конца тела; см. ниже |
| `0x00` | конец тела | — |

Размер в секциях `0x08`, `0x09`, `0x0c` **включает само поле размера**: после
`u32 size` читается `size − 4` байт.

### Переменные (`0x0f`)

Запись: `str имя`, `str описание`, `str значение по умолчанию`, `str тип`,
`u32 флаги`.

Типы в корпусе: `FLOAT` (4978), `HANDLE` (854), `STRING` (486), `COLORREF`
(164). Объявленные в справке `INTEGER`, `WORD`, `BYTE`, `POINTER` в файлах не
встречаются.

Флаги (наблюдаемые значения — `0x20000`, `0x20080`, `0x20082`, `0x20100`,
`0x20002`, `0x20200`, `0x80`, `0x20480`):

| бит | Значение |
| --- | --- |
| `0x00000002` | локальная (`local` в тексте) |
| `0x00000080` | вычисляется самим имиджем |
| `0x00000100` | вход |
| `0x00000200` | выход |
| `0x00000400` | двунаправленная |
| `0x00020000` | взведён у всех переменных файлов v3.002 и v3.003 |

### Дочерние имиджи схемы (`0x11`)

Запись: `str имя класса`, `u16 handle`, `str имя экземпляра` (пустая, если
экземпляр не переименован), координаты, `u8 флаги`.

Координаты: два `f64` начиная с версии 3.002; в версии 3.001 — два `i16`
(пиксели).

`handle` — идентификатор экземпляра на схеме, на него ссылаются связи.

### Связи (`0x07`)

Запись: `u16 handle источника`, `u16 handle приёмника`, `u16 собственный
handle`, `u32 флаги`, `u16 число пар`, `u16 резерв`, далее пары
`str имя переменной у источника`, `str имя переменной у приёмника`.

Резервное слово обычно 0, но не всегда (в старых файлах встречаются иные
значения), поэтому число пар нужно читать именно как `u16`, а не как `u32`.

### Уравнения (`0x1e`)

55 файлов в `add.lib/CHAINS`, `add.lib/CHAINS/STATIC` и `add.lib/TOE.LIB` —
библиотеки электрических цепей, единственные, где используются уравнения
(запись через `=`, решаемая средой). Секция всегда идёт последней в теле, за
ней сразу следует отметка времени (либо конец тела). Внутренняя структура —
похоже, такой же 16-битный байт-код, как в секции `0x0d`; пока читается
как непрозрачный блок и сохраняется в исходном виде.
